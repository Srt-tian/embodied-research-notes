CODING SKILL/PDB POST MORTEM
SKILL 01 · DEBUGGING

异常发生后，
直接进入现场。

pdb.post_mortem() 会在异常发生后进入保存着报错现场的 traceback。无需提前猜测断点位置，就能检查当时的调用栈和局部变量。

ON THIS PAGE核心区别复制模板现场命令适用边界
01 · CORE IDEA

提前埋点与事后勘察

pdb.set_trace()

程序正常运行到预先放置的位置时暂停。适合验证某段流程，但需要先猜到问题大概在哪里。

pdb.post_mortem()

异常发生后沿 traceback 回到报错现场。适合偶发错误、深层调用报错，以及不确定该在哪里下断点的情况。

02 · COPY TEMPLATE

最小可用模板

try:
    train()
except Exception:
    import pdb
    pdb.post_mortem()
为什么有效

except 捕获异常时，当前异常的 traceback 仍然存在；post_mortem() 利用它启动调试器，因此你看到的是出错那一刻的栈帧与变量。

03 · FIELD COMMANDS

进入现场后先做什么

命令作用现场用途
bt显示完整调用栈判断异常从哪条调用链传来
p variable查看变量或表达式检查 shape、dtype、索引与路径
u / d切换上层 / 下层栈帧回到自己的调用代码查看输入来源
l显示附近源码把当前变量与具体代码对上
q退出调试器结束现场检查
04 · BOUNDARY

别让调试模板吞掉错误

IMPORTANT

适合本地诊断，不应原样留在正式训练任务里。

无人值守训练、CI 或线上服务没有人输入命令，进程可能一直挂住。定位完成后删除包装，或只在明确的 debug 开关下启用。

if debug:
    try:
        train()
    except Exception:
        import pdb
        pdb.post_mortem()
        raise
else:
    train()

raise 会在退出调试器后重新抛出原异常，让任务仍以失败状态结束，避免日志或调度系统将它误判为成功。
